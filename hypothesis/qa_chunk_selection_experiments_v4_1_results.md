## 1. Что это за эксперимент

После V4 два сигнала выглядели обоснованными, но с дырами в оценке:

- **V6** reader-centered rerank внутри B0 top-K. В V4 веса брались с **одного** CAL-фолда и применялись на весь unlocked пул. Hit@1 42.60%, Token F1 35.04, ΔF1 +7.69.
- **V2-A4** агрегация ответов: `max(B0)+λ log(1+N_clusters)`, λ=1.0. Ranking не меняется, Token F1 30.26, ΔF1 +2.90.

V4.1 должен был:

1. Починить pairing / bootstrap / shortlist isolation / role reporting / pairwise scale.
2. Сделать **честный 5-fold OOF** для V6 (R1).
3. Заморозить веса R1 и снять knockouts A0–A7 (R2).
4. Собрать C1 = softmax(V6) внутри top-K + `λ_agg log(1+N_clusters)` (R3), не подставляя сырой V6-score в старую λ.
5. Отдельно сравнить fixed K=5 и fixed K=10 (R4), не выбирая K по EVAL-фолду.
6. Не открывать INTERNAL_TEST.

Не развивались: KeyBERT/LOSCO, ownership, V7, raw QA ranking, softmax-only как ranker, QA-silver, ручной TE/TM, attention-only, старый SpanRanker.

Формула V6 (шкала V4, без нормализации 0..1):

```text
S = α * b0_score + β * (exact_freq + mean_token_f1 + majority) + γ * source_clusters
```

`mean_token_f1` — SQuAD F1 **0..100**, `exact_freq` — счётчик 0..K−1, `majority` — 0/1, `source_clusters` — число overlap-кластеров (порог 0.6).

Primary K=5. Сетка `FUSION_LAMBDAS = {0, 0.25, 0.5, 1.0, 2.0}` по α, β, γ → 125 точек, записана в `contract.json` до EVAL. HN-фильтр на CAL: HN@1 ≤ HN@1(B0 CAL) + 0.02.

## 5. R2 — knockouts на замороженных R1-весах

Без ретюнинга. A4 и A5 на frozen weights — одна и та же формула (γ=0 / «B0+agreement без support»).

| full V6 | R1 OOF | 34.62 | 42.90% | 5.45% | +7.26 | 0 | — |
| A1 | − exact_freq | 34.67 | 42.97% | 5.45% | +7.30 | +0.04 | [0.00, 0.13] |

Чтение (диагностика, не новая model search):

1. **A0 точно B0** — isolation и knockout-код не сломаны.
2. **Agreement — основной источник gain.** Без него (A6) остаётся слабые +2.2 F1.

### 6.2. C1 — primary combination

Протокол: softmax V6 **внутри top-K как веса evidence**, затем

```text

win/lose/tie vs V6 = 2 / 2 / 1355
```

## 9. Автоселекция vs freeze vs протокол

`analysis/selection.json`:

```text

IN_SAMPLE_CONTAMINATED = false
```

Правила compare:

- в auto-winner только `PRIMARY_FINAL_SYSTEMS`;
- три seed;
- HN ok;
- для V6/C1 CI vs B0 не содержит 0.

Все четыре кандидата прошли vs B0. Потом выбран максимальный Token F1 → K=10.

Это **сравнение с B0**, не тест «K=10 лучше K=5». Freeze отдельно:

```text
final_architecture = V6-K10     # из compare
final_k            = 5          # K10 vs K5 CI includes 0
global V6 weights  = (0.0, 0.25, 2.0)   # argmax mean CAL F1 по 125×5
global λ_agg       = 0.0
b0_final trained   = false
internal_test      = locked
utility_branch     = excluded
```

Global `(0, 0.25, 2.0)` выиграл mean CAL Token F1 **35.59** по пяти runs (HN 5.88% ≤ B0 CAL 4.85%+2%). **Ни один outer EVAL не оценивал именно эту тройку как единственные веса на всём пуле.** OOF 34.62 — смесь пяти разных троек. Если когда-нибудь открывать INTERNAL_TEST, честный объект — «процедура V6 K=5 + global CAL weights», и его test-число не обязано совпасть с 34.62.

Научная рекомендация freeze (не autodump):

```text
architecture = V6
K            = 5
aggregation  = нет (C1 не помог)
λ_agg        = 0, если вдруг C1
R5           = не в этом прогоне
INTERNAL_TEST = пока не открывать
```

K=10 остаётся exploratory sensitivity: выше точка, нет статистического отделения от K=5, хуже Hit@5, дороже reader.

## 12. Что из этого следует

1. Дыры V4 в оценке закрыты: pairing, bootstrap, B0 identity, pairwise scale, shortlist isolation, role/OOF merge, репродукция V6 и V2-A4.
2. Reader-centered rerank внутри B0 top-5 — воспроизводимый OOF-сигнал, не артефакт одного CAL-фолда. Честная цена — около **0.4 F1** относительно frozen V4 V6.
3. Агрегация V2-A4 по-прежнему даёт +2.9 F1 без смены чанка, но **поверх V6 не работает** (λ=0). Имеет смысл как более простой pipeline **вместо** V6, не как надстройка. Pareto: V2-A4 проще и слабее; V6 сильнее и требует QA на shortlist.
4. K=10 не готов стать default. Нужен либо более мощный тест vs K=5, либо явное принятие регресса Hit@5.
5. Веса V6 нестабильны. Имеет смысл в следующем цикле упростить формулу (majority + слабый B0 / без exact_freq / осторожнее с Token-F1 0..100), а не тащить 125-сетку как «модель».
6. R5 U80 ещё предстоит, если utility-ветка вообще нужна. Этот прогон её не закрыл и не открыл.
7. INTERNAL_TEST по-прежнему рано открывать, если цель — confirmatory test **одной** замороженной системы. Если открывать, то на **V6 K=5** с явным манифестом весов, не на autodump K=10.
