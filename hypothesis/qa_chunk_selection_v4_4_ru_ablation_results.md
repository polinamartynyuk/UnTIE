# Результаты V4.4-RU ablations и BGE cross-encoder

Дата анализа: 13 сентября 2026 года.

Проанализирован завершённый артефакт
`artifacts/qa_chunk_selection_v4_4_ru_ablation_20260912_230234`. Прогон завершился
успешно (`exit_code=0`) за 7534.12 с, то есть примерно за 2 ч 5 мин 34 с.

## 1. Главный вывод

Самый сильный и устойчивый результат эксперимента дал новый multilingual
cross-encoder `BAAI/bge-reranker-v2-m3`. Его OOF Token F1 равен **69.9535** против
**52.7683** у исходного русского B0: прирост составляет **+17.1669 F1**, а 95%
development CI равен **[+14.0657; +20.1521]**. Одновременно Hit@1 вырос с 52.56%
до 72.57%, MRR — с 0.7082 до 0.8402, а HN@1 снизился с 21.39% до 6.56%.

Это означает, что основная проблема предыдущего русского V4.4 находилась в
базовом ранжировании чанков. Более подходящий cross-encoder исправляет её намного
сильнее, чем reader-consensus надстройки.

После усиления B0 дополнительный V4.4-слой практически везде корректно выбрал
fallback к B0. При K=4 и K=5 все варианты V6, SEM, LEX, LEX-LEM, ASEM и ASEM-Q5
совпали с BGE B0. При K=3 V6 изменил несколько решений и ухудшил F1. Поэтому
**лучшей проверенной русской конфигурацией сейчас является BGE B0**, без
reader-consensus reranking.

## 2. Что именно проверялось

Эксперимент использовал тот же общий метод V4.4 и отдельно проверял русские
гипотезы:

1. выбор наиболее успешной формулировки вопроса для каждого из девяти аспектов;
2. подбор русских коэффициентов на TRAIN+CAL без использования outer EVAL;
3. сравнение shortlist K=3, K=4 и K=5;
4. отдельные SEM, LEX и лемматизированный LEX-LEM reader-сигналы;
5. адаптивный SEM-router ASEM и ASEM-Q5 с дополнительным Q5-consistency veto;
6. диагностическое объединение связанных аспектов без изменения исходных меток;
7. замену русского B0 cross-encoder на `BAAI/bge-reranker-v2-m3`.

`s-nlp/ruRoberta-large-paraphrase-v1` в этом прогоне не использовалась, как и
было решено перед запуском.

Исходными данными служил read-only артефакт
`qa_chunk_selection_v4_4_ru_q5_b0_20260912_172431`. Зафиксированы SHA-256 четырёх
ключевых входов: answerable dataset, grouped CV splits, Q5 prediction cache и
исходные B0 OOF predictions. Новый эксперимент писал результаты только в новый
timestamp-каталог и не перетирал прежние артефакты.

## 3. Корректность протокола

В анализе 508 answerable вопросов, 300 документов и 1524 OOF-строки
(508 вопросов × seeds 42, 43, 44). Использованы пять document-grouped outer
folds. Для каждого outer run выбор формулировки вопроса, коэффициентов и правил
routing выполнялся только на TRAIN+CAL; число документов EVAL, попавших в выбор
вопроса, равно нулю.

Новый cross-encoder обучался 15 раз: 5 outer runs × 3 seeds. Во всех случаях
исходная regression head модели имела один label и не переинициализировалась;
веса backbone сохранялись. Использовались bf16, effective batch size 16,
максимальная длина 512 и objective с уникальными парами в отношении
positive:hard-negative:easy = 1:3:1. Каждый `question_id` получал одинаковый
суммарный вес, oversampling hard negatives отсутствовал.

Число обучающих пар менялось лишь от 785 до 800. Выбранная calibration PR-AUC по
15 моделям находилась в диапазоне 0.8561–0.9157, среднее — 0.8904. Pairwise
clean-HN находился в диапазоне 0.8676–0.9372, среднее — 0.9067. Лучшие эпохи:
эпоха 1 — один раз, 2 — три раза, 3 — один раз, 4 — четыре раза, 5 — шесть раз.
Это не показывает единого оптимального числа эпох, но ранняя остановка работала,
а качество calibration не разваливалось ни в одном fold/seed.

Веса 15 fold-моделей после OOF-scoring намеренно не сохранялись. Сохранены полные
OOF predictions и training reports. Поэтому результат воспроизводим как оценка,
но для применения BGE на новых данных потребуется отдельное финальное обучение
модели на всём разрешённом training-наборе.

## 5. Выбор основного вопроса

Для каждого outer run на TRAIN+CAL выбиралась Q5-формулировка с максимальной
долей `qa_correct` внутри аспекта. Получился следующий выбор:

| Аспект | Выбранные question IDs в runs 0–4 | Стабильность |
| --- | --- | --- |
| advantage | 1, 1, 1, 1, 1 | полностью стабильный q1 |
| conclusion | 0, 0, 0, 0, 0 | полностью стабильный q0 |
| contribution | 1, 1, 1, 4, 4 | q1/q4 |
| example | 1, 0, 2, 0, 0 | нестабильный q0/q1/q2 |
| goal | 0, 0, 0, 0, 0 | полностью стабильный q0 |
| method | 1, 1, 1, 0, 1 | в основном q1 |
| task | 1, 1, 1, 1, 1 | полностью стабильный q1 |
| tool | 0, 4, 3, 0, 4 | нестабильный q0/q3/q4 |
| use | 0, 0, 0, 0, 0 | полностью стабильный q0 |

Гипотеза реализована корректно, но не дала подтверждённого улучшения на EVAL.

Для исходного B0 переход от q0 к выбранным вопросам изменил F1 на **−0.4336**,
95% CI **[−2.4495; +1.5531]**. Для BGE B0 изменение равно **+0.0916**, 95% CI
**[−2.0693; +2.2179]**. Оба интервала широко пересекают ноль.

На BGE абсолютный максимум среди двух question strategies действительно у
`selected` B0: 70.0239 против 69.9535 у q0. Разница +0.07 слишком мала и
неустойчива, поэтому её нельзя использовать как основание для замены q0.
Практический вывод: оставить q0 как стабильный default, а переформулировку
вопроса исследовать позже с более сильным критерием и отдельным test-набором.

## 6. Русские коэффициенты и ablations reader-сигналов

Подбор коэффициентов показал, какие компоненты реально несут полезный сигнал.
Для исходного B0 при q0:

- K=3 выбирал V6-веса с `beta=0`, `gamma=0.25`; `alpha` менялся между 0.5, 1 и 2;
- K=4 и K=5 во всех пяти runs выбрали `(alpha=2, beta=0, gamma=0.25)`;
- SEM во всех 30 ячейках `2 strategies × 3 K × 5 runs` выбрал нулевые веса;
- при K=4 и K=5 LEX и LEX-LEM также всегда выбрали нулевые веса;
- ненулевой LEX/LEX-LEM встречался лишь в отдельных K=3 source folds и не
  перенёсся в положительный общий OOF-результат.

Таким образом, небольшой прирост исходного V6 создаётся базовым score и
source-cluster support (`gamma`), а не согласием QA-ответов (`beta=0`) и не
SEM/LEX reader-сигналами.

Для BGE результат ещё строже:

- при q0 K=3 три runs выбрали fallback B0, два — `(2, 0, 0.25)`;
- при selected K=3 четыре runs выбрали fallback, один — `(2, 0, 0.25)`;
- при K=4 и K=5 все десять strategy/run комбинаций выбрали fallback B0;
- SEM, LEX и LEX-LEM получили нулевые дополнительные веса во всех ячейках.

Это хороший признак работы защитного протокола: когда BGE уже ранжирует лучше,
подбор не навязывает ему слабые reader-признаки.

## 8. ASEM и Q5-consistency veto

На исходном B0 ASEM без Q5-veto часто портил часть переключений V6 → reader.
Q5-veto снижал этот вред:

| Ячейка | ASEM F1 | ASEM-Q5 F1 | V6 F1 | Эффект Q5-veto к ASEM |
| --- | ---: | ---: | ---: | ---: |
| q0, K=4 | 53.1260 | **53.3031** | 53.3702 | +0.1772 |
| q0, K=5 | 53.2318 | **53.4090** | 53.4067 | +0.1772 |
| selected, K=4 | 52.2600 | **52.5520** | 52.6323 | +0.2920 |
| selected, K=5 | 52.4345 | **52.7452** | 52.8797 | +0.3107 |

При q0/K=5 ASEM изменил относительно V6 25 top-1 решений: 9 были полезными и
11 вредными. ASEM-Q5 пропустил только 22 изменения: 9 полезных и 8 вредных.
Итог ASEM-Q5 практически совпал с V6: +0.0023 F1. При selected/K=5 Q5-veto
также уменьшил вред, но остался ниже V6 на 0.1345 F1.

Следовательно, Q5-consistency работает как safety filter, но самостоятельного
прироста не создаёт. При K=3 ASEM и ASEM-Q5 вообще не меняли top-1 относительно
V6. На BGE reader-веса равны нулю, поэтому формальные срабатывания router не
изменяют top-1: считать их содержательными переключениями нельзя.

## 9. Лемматизация

Лемматизация полезна как вторичная метрика качества русских ответов:
BGE повышает Lemma F1 с 54.6333 до 70.7387. Она подтверждает тот же крупный
эффект, что Token F1, и не меняет общий вывод.

Лемматизация как отдельный ranking-сигнал `LEX-LEM` не подтвердилась. Для
исходного q0/K=3 LEX-LEM дал 52.0255, то есть −0.7454 к B0; при K=4 и K=5
подбор занулил его и вернул B0. Для BGE он был занулён во всех K и обеих
стратегиях. Поэтому лемматизацию следует сохранить для финальной оценки F1, но
не включать в основной reranking без новой независимой гипотезы.

Важно: поле `rouge_l_f1` в верхнем `cross_encoders/bge_m3/metrics.json` было
посчитано прежним способом и равно 0.1160; оно некорректно отражает русский
текст. Для выводов использовано повторное protocol-вычисление Unicode ROUGE-L:
0.7008 для BGE q0 B0. Смешивать эти два значения нельзя.

## 10. Диагностика связанных аспектов

Исходные aspect labels не объединялись. Пары анализировались только как pooled
диагностика, поэтому эта часть не проверяет причинный эффект обучения на
объединённых метках.

| Диагностическая группа | N | Исходный B0 F1 | BGE B0 F1 | Изменение |
| --- | ---: | ---: | ---: | ---: |
| task + goal | 360 | 60.5185 | **74.2366** | +13.7181 |
| method + tool | 462 | 53.4678 | **70.6417** | +17.1739 |
| task + use | 519 | 49.9994 | **69.9857** | +19.9863 |
| contribution + conclusion | 219 | 55.4293 | **66.9080** | +11.4787 |

BGE улучшает все диагностические группы, но из этого не следует, что аспекты
надо сливать. Более безопасный следующий шаг — multi-task/shared representation
с сохранением девяти отдельных меток либо отдельный controlled ablation с
объединением только в training. Текущий эксперимент не даёт основания менять
семантику датасета.

## 11. Сопоставление с прежними EN/RU результатами V4.4

В английском V4.4 reader-сигналы были заметно полезнее: SEM-FIX давал около
+2.89 F1 к английскому V6. В предыдущем русском V4.4 перенесённые reader-формулы,
напротив, ухудшали результат, а русский V6 был ниже русского B0.

Новый эксперимент уточняет причину:

- русский cross-encoder действительно был главным узким местом;
- multilingual BGE резко усилил B0 сразу на всех аспектах и folds;
- после этого русские reader-consensus признаки всё ещё не показывают полезного
  независимого сигнала: tuner систематически присваивает им нулевые веса;
- единая концепция метода сохраняется, но оптимальная точка русского пайплайна
  сейчас находится раньше adaptive reader routing — на сильном B0.

Абсолютные EN и RU значения F1 напрямую сравнивать нельзя: различаются наборы,
аспекты, число кандидатов и модели. Сравнивать следует прирост относительно
собственного B0/V6. В этом смысле русский результат BGE (+17.17 F1 к старому B0)
намного сильнее всех проверенных русских reader-ablation, а последующий V4.4
слой не улучшает новый baseline.

## 12. Решения по исходным гипотезам

| Гипотеза | Вердикт | Основание |
| --- | --- | --- |
| Выбирать самый успешный вопрос по аспекту | не подтверждена | +0.09 F1 на BGE, CI широко включает 0; часть аспектов нестабильна |
| Подбирать отдельные русские коэффициенты тем же методом | подтверждена как процедура | tuner правильно выбрал `beta=0`/fallback и защитил сильный BGE |
| Для русского лучше top-3 | опровергнута текущими данными | исходный B0 лучше при K=5; BGE при K=3 ухудшается, K=4/5 дают fallback |
| Объединить пары аспектов | пока не проверена причинно | pooled-диагностика положительна, но обучение на объединённых метках не выполнялось |
| Лемматизация только для финального F1 | подтверждена | Lemma F1 полезен как метрика; LEX-LEM не улучшает ranking |
| Q5-consistency veto | частично подтверждена | уменьшает вред ASEM, но не превосходит V6/B0 устойчиво |
| Более подходящий multilingual cross-encoder | сильно подтверждена | +17.17 F1, CI полностью выше 0, улучшение во всех folds/seeds/aspects |

## 13. Практический выбор и следующие эксперименты

Для текущего русского пайплайна следует зафиксировать как development winner:

1. `BAAI/bge-reranker-v2-m3` B0;
2. канонический q0 как default, поскольку преимущество selected questions не
   доказано;
3. без V6/SEM/LEX/LEX-LEM/ASEM reranking;
4. Token F1 как основную и Lemma F1 как вторичную русскую метрику;
5. Unicode ROUGE-L из protocol-вычисления.

Следующий содержательный шаг — не расширять сетку reader-коэффициентов, а
проверить новый BGE B0 на независимом test-наборе. Текущие confidence intervals
являются development CI: данные уже многократно использовались для выбора
гипотез, поэтому остаётся selection bias. После независимой проверки можно:

- обучить одну финальную BGE-модель на всём разрешённом training-наборе;
- изучить ошибки оставшихся 27.43% случаев без positive на rank 1, особенно
  аспекты `contribution`, `advantage` и `use`;
- отдельно исследовать learned router на OOF-признаках, если сохраняется цель
  развивать reader consensus;
- проверить shared training для близких аспектов без слияния evaluation labels;
- возвращаться к выбранным Q5-вопросам только при более устойчивом nested-CV или
  отдельном validation/test split.
