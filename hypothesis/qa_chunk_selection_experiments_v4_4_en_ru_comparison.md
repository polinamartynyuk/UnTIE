# V4.4: сопоставление английского и русского экспериментов

Дата анализа: **2026-09-12**.

Этот отчёт сопоставляет завершённые development-прогоны V4.4:

- английский: `artifacts/qa_chunk_selection_v4_4/`;
- русский: `artifacts/qa_chunk_selection_v4_4_ru_20260912_191024/`.

Числа взяты из сохранённых артефактов. Дополнительные разрезы рассчитаны из
`predictions_scored.jsonl`; обучение, QA inference и повторный экспериментальный
прогон не выполнялись.

## 1. Основной вывод

**Русский эксперимент не подтвердил перенос эффекта английской V4.4. В обоих
языках формальным development-кандидатом остаётся V6-K5, но причины различаются.**

В английском ASEM повышает Token F1 относительно V6 на **+0.4863** с формально
положительным development CI **[+0.0054; +0.9928]**, однако снижает Hit@1 на
**1.0302 п.п.** при допустимой потере 0.5 п.п. Поэтому H1 не проходит.

В русском ASEM снижает Token F1 на **−0.7638**; bootstrap-оценка равна
**−0.7661**, CI **[−2.0942; +0.5404]**. Одновременно Hit@1 падает на
**1.2467 п.п.** H1 не проходит сразу по трём условиям: положительному эффекту,
нижней границе CI и Hit@1.

Для русского языка есть более фундаментальная проблема: V6-K5 хуже исходного
B0-live на **1.7383 F1**, **3.3465 п.п. Hit@1** и **0.9186 п.п. HN@1**. Поэтому
записанное в manifest значение `preferred=V6-K5` означает только победителя
внутри предусмотренного протоколом сравнения `ASEM vs V6`. Оно не означает, что
русский V6 следует предпочесть русскому B0. По фактическим данным **русский B0
остаётся лучшей безопасной исходной системой из проверенной цепочки**.

Английские fixed readers дают сильный положительный сигнал, а русские — общий
отрицательный:

- EN SEM-FIX: **+2.8859 F1** к V6; RU SEM-FIX: **−3.5258**;
- EN LEX-FIX: **+2.3568 F1**; RU LEX-FIX: **−4.5749**;
- EN ASEM: **+0.4864 F1**; RU ASEM: **−0.7638**;
- EN ALEX: **+0.1494 F1**; RU ALEX: **−0.8085**.

Это указывает не только на слабость Q70-router, но и на отсутствие общего
положительного reader-consensus сигнала в русском наборе при перенесённых
фиксированных формулах.

## 3. Насколько эксперименты сопоставимы

Архитектурный вопрос совпадает: может ли feature-only router безопасно выбирать
между V6 и reader-consensus ранжированием внутри точного B0 top-5. Совпадают K=5,
три seeds, document-grouped CV, формулы SEM-FIX/LEX-FIX, Q70, H1/H2 gates и
seed-aware document-clustered bootstrap.

Однако это не два измерения на одном распределении.

| Характеристика | Английский | Русский |
| --- | --- | --- |
| Вопросы | 453 | 508 |
| Документы | 240 | 300 |
| Строки на систему | 1359 | 1524 |
| Аспекты | 4 | 9 |
| Общие аспекты | task, method | task, method |
| Среднее кандидатов | 19.75 | 4.05 |
| Медиана кандидатов | 19 | 4 |
| Диапазон кандидатов | 4–42 | 1–9 |
| Не менее 5 кандидатов | 99.78% строк | 43.90% строк |
| Семантическая модель | all-MiniLM-L6-v2 | rubert-base-cased-sentence |
| V6-веса | frozen из V4.1 | выбраны на CAL отдельно в каждом run |
| ROUGE-L | прежняя Latin-compatible реализация | Unicode word-LCS |
| Independent test | существует, но locked | отсутствует |

Поэтому абсолютные F1, Hit@K, HN@K и ROUGE-L между языками нельзя трактовать как
прямое соревнование качества. Корректнее сравнивать направление и величину
изменений относительно собственного B0/V6 каждого языка.

Особенно различается Hit@5. В русском наборе у 56.10% строк вообще меньше пяти
кандидатов, а максимум равен девяти; Hit@10 автоматически равен 100%. В английском
95.58% строк имеют не менее десяти кандидатов. Русский Hit@5=97.90% и английский
Hit@5=79.03% отражают в том числе разный размер candidate universe.

## 6. Русский V6: CAL-выбор и перенос на EVAL

До V4.4 отдельного русского V6 не было, поэтому его веса выбирались внутри
каждого outer run только по CAL. Это сохраняет EVAL от прямой утечки, но создаёт
отличие от английского эксперимента, где использовались ранее frozen V4.1 weights.

| Run | Выбранные `(α, β, γ)` | CAL ΔF1 V6−B0 | EVAL ΔF1 V6−B0 |
| ---: | --- | ---: | ---: |
| 0 | (1.0, 0.25, 0.0) | +1.4940 | **+3.0817** |
| 1 | (2.0, 0.25, 0.0) | +3.5232 | **−11.1728** |
| 2 | (0.25, 0.0, 0.0) | 0.0000 | 0.0000 |
| 3 | (0.25, 0.0, 0.25) | +1.9215 | **−0.9072** |
| 4 | (0.25, 0.0, 0.0) | 0.0000 | 0.0000 |

Runs 2 и 4 выбрали чистое масштабирование B0, поэтому ранжирование не изменилось.
Run 0 перенёс улучшение. Run 3 дал небольшую EVAL-деградацию. Run 1 показал
резкий distribution shift: CAL обещал +3.52 F1, а EVAL получил −11.17 F1. Именно
этот run в основном объясняет общий проигрыш V6 относительно B0.

Это не утечка: независимая проверка показала нулевое пересечение EVAL с
калибровочными источниками. Напротив, это свидетельство слабой переносимости
выбранных reader-agreement весов между русскими folds. При 300 документах и
неравномерном распределении девяти аспектов один calibration fold оказался
недостаточным для устойчивого V6 выбора.

Протокольный precision включает F1-ties в знаменатель и поэтому скрывает важное

Русский router меняет top1 немного чаще английского, несмотря на гораздо более
низкую availability, но ошибается чаще, чем выигрывает. Суммарный F1-эффект
фактических ASEM-переключений равен **−1163.98 F1-пункта по строкам**, что даёт
общий средний проигрыш около −0.764. Для ALEX сумма равна −1232.21.

## 8. Почему в русском routing реже доступен

Распределение `n_valid` в русском confidence cache:

| Valid answers в shortlist | Строк | Уникальных вопросов | Доля |
| ---: | ---: | ---: | ---: |
| 1 | 219 | 73 | 14.37% |
| 2 | 189 | 63 | 12.40% |
| 3 | 174 | 58 | 11.42% |
| 4 | 273 | 91 | 17.91% |
| 5 | 669 | 223 | 43.90% |

Semantic similarity pack доступен при ≥3 valid answers: 1116/1524 строк, или 73.23%.
Для ConsensusConf нужны минимум четыре ответа, поэтому конечный confidence есть
только у 942/1524 строк, или 61.81%. После условия «выбранный reader входит в
лучшую тройку» routing availability снижается до 56.89% для ASEM и 52.43% для
ALEX.

В английском confidence был конечным во всех 1359 строках: 1356 имели пять valid
answers и три — четыре. Таким образом, правило «не менее четырёх ответов» было
естественным для английского top-5, но исключает 38.19% русского пула из routing
ещё до применения Q70.

### 8.1. Эффект по фактическому размеру shortlist

Размер 5 в таблице означает пять или более кандидатов, поскольку V4.4 использует
не более top-5.

| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 219 | 86.4174 | 0.0000 | 0.0000 | 0.0000 | 0.00% | 0.00% |
| 2 | 189 | 56.2221 | −4.4919 | −0.6847 | 0.0000 | 0.00% | 0.00% |

Router по определению ничего не меняет при 1–3 кандидатах. При четырёх он даёт
небольшой положительный эффект, а на полном top-5 — заметный отрицательный.
Следовательно, общая деградация ASEM сосредоточена в наиболее конкурентной части
русского пула, а не вызвана fallback на коротких документах.

## 13. Интерпретация и дальнейшие решения

1. **Не заменять русский B0 текущим V6/ASEM/ALEX.** B0 лучше по F1, retrieval и
   HN safety. Формальный V4.4 manifest не сравнивал право V6 заменить B0.

2. **Считать исходную русскую гипотезу V4.4 отрицательной.** Перенесённые
   SEM-FIX/LEX-FIX формулы не дают общего улучшения, а hard Q70-router выбирает
   больше вредных, чем полезных нетривиальных переключений.

3. **Перед следующим русским адаптивным экспериментом стабилизировать V6.**
   Нужен отдельный nested протокол выбора V6 с guard относительно B0 не только по
   HN, но также по F1/Hit@1, либо безопасный fold-level fallback к B0. Run 1
   показывает, что CAL-максимизация F1 без проверки переносимости недостаточна.

4. **Учесть короткие candidate lists.** Для 38.19% русских строк невозможно
   вычислить текущий ConsensusConf. Возможная следующая гипотеза должна заранее
   определить поведение при 1–3 кандидатах и не переносить английское правило
   availability автоматически.

5. **Исследовать аспектную неоднородность только новым протоколом.** `tool`,
   `goal`, `use` дают положительный сигнал, а `task`, `contribution`, `example` —
   отрицательный. Aspect-aware routing или отдельные веса имеют смысл как новый
   эксперимент с nested selection, а не как post-hoc исправление V4.4.

6. **Пересмотреть confidence target.** В обоих языках ConsensusConf
   немонотонен; в русском почти все квинтили reader-disagreement отрицательны.
   Следующий router должен прогнозировать ожидаемую пользу/риск переключения на
   TRAIN/CAL, сохраняя EVAL закрытым, либо использовать более консервативное
   правило с явным B0/V6 safety fallback.

7. **Не делать вывод о local support.** В обоих прогонах support закономерно
   пропущен после H1 fail. Для него нет эмпирического результата.

## 14. Итоговый статус гипотез

| Гипотеза | Английский | Русский |
| --- | --- | --- |
| V6 лучше B0 | поддерживается | **не поддерживается** |
| Fixed semantic reader полезен по F1 | поддерживается описательно | **не поддерживается в целом** |
| ASEM даёт положительный ΔF1 | да, слабый development signal | **нет** |
| ASEM проходит H1 | нет: Hit@1 | нет: F1, CI, Hit@1 |
| ALEX можно выбрать по H2 | нет, H2 skipped | нет, H2 skipped |
| ConsensusConf монотонен | нет | нет |
| Local support полезен | не проверено | не проверено |
| Готовность к deployment/test | нет | нет |

Главное научное различие состоит в том, что английский эксперимент обнаружил
полезный reader-сигнал, который router реализует слишком небезопасно, тогда как
русский эксперимент обнаружил и слабый/аспектно неоднородный reader-сигнал, и
неустойчивый V6 baseline. Поэтому русская следующая итерация должна начинаться с
защиты B0 и устойчивого выбора V6, а не с тонкой настройки текущего Q70.
